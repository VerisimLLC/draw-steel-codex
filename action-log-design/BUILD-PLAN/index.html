    History: build plan¶

    Status: signed off by James, 2026-11-06. Design: BRIEF.md, REVIEW.md, COPY.md, prototype https://claude.ai/artifact/UPWo9XvYuaDiZ388xRES35 (version 26).

    How the work runs¶

    • One chunk, one commit. Each stage is still one PR, but none goes up until the build is finished; then they are raised together (James, 2026-11-06), so a late change to an earlier stage's files needs no extra PRs. Everything stays behind an off-by-default setting.
    • A tag marks where each stage ends: history-stage-0, history-stage-1 and so on. Each stage works on feature/history-stage-N, cut from the last stage's tag. Tags and branches stay local until the PRs go up. Merge main in at each stage end, since these files change often there.
    • History runs beside the old log until the last stage. The old log and its messages stay untouched. The switch-over is one chunk.
    • History never breaks the game. Every hook sits in hot combat code, so each is wrapped the way LiveEncounter.TrackHeroStats is: it can fail, and the cast carries on.
    • Generic hooks only. No code for a particular ability. Content built from modifiers works without changes, including future content.
    • Wording comes from COPY.md. Anything not there gets proposed first.
    • Every chunk: smoke test in the Codex over the bridge, type check, ASCII only, new Lua files registered through the MCP CodeMod workflow, the UI performance rules. James clicks where nothing can be checked by script. data/ YAML is only edited with the Codex closed.
    • Layering: hooks in DMHub Game Rules/ stay system-neutral, with Draw Steel words in the Draw Steel layer, so Crows keeps working. Check Crows loads after stage 0.

    Stage 0 notes (built 2026-11-06)¶

    • Entries are JSON strings, not tables (PROBE-0.1.md), and the hard cap is 500. The tray parses only the rows it builds.
    • Written when the cast ends, stamped with when it began, so a cancelled cast leaves nothing and one action is one write. Stage 1 should add a cast's results to its entry before that write.
    • The setting is historyenabled, game-wide, with no UI: dmhub.SetSettingValue("historyenabled", true). It has no wording yet because it never reaches a screen. Turning it on puts the rail button below Chat for that user (PanelDocument.RailPlaceBelow); 6.4 can use the same call.
    • Generic hooks added: ActivatedAbility.RegisterCastObserver, available on a panel registration, place, Tabletop.HasItem, Tabletop.CloseItem and Tabletop.ResizeItem for table items, and InitiativeQueue.turnNumber, a running count, because turn starts again each round.
    • Measured at 485 entries: tray open 70 ms of Lua, worst frame 150 ms; Show all 89 ms; a new row under 35 ms with its cast; idle open equals closed (14 ms); dragging 22 ms a frame against 25.6 ms for a map window. Panel count stays flat.
    • Left for later, not in stage 0's list: the Main, Maneuver and Move markers (T8: Move is not recorded yet), the Draw Steel banner (T10), chips (T12), the hover titlebar's text (T2), the rail button's lit state while the tray is open, and text for an empty tray, which has no signed wording.
    • Cloud file list: History, HistoryCapture and HistoryTray are registered in Draw Steel V now, ahead of the code reaching main. A client without the files on disk runs the empty cloud stubs, so History simply isn't there for anyone on main until the PRs merge.
    • Not checked: Crows. Crowdex/ is not in this checkout and does not load in the test game. History is inert while the setting is off, but check a Crows game before merging.

    Stage 1 notes¶

    • 1.1 hooks moved, for the better. creature.TakeDamage and creature.Heal instead of the damage and heal behaviors: every route ends there, hand edits and falls included, and they know the number that landed. SetTemporaryHitpoints instead of GrantTemporaryStamina, so ongoing effects count.
    • One observer: GameSystem.RegisterPlayObserver replaces the cast observer. Later families add a moment to it, not a new mechanism.
    • Writes batch per frame. History.Write queues; an aura hitting eight creatures is one write.
    • Measured per hit: 1 us with History off, 3 us inside a cast, 40 us for a line, plus the write.
    • 1.2: events carry causecastid, which survives the trip to another client. A trigger's entry names its cause and the tray nests it, so client and order don't matter, and nothing rewrites the parent.
    • Prompted triggers stay action rows (REVIEW.md section 1). A prompted trigger does not nest yet; "Before the roll" and "After the roll" (T15) need roll data from stage 2.
    • 1.3: creature:EndingEffects(cause, fn) wraps every place something comes off a creature and works out what ended from what changed, so a new removal path needs one wrapper, not its own logic. Lapsed timers are cleared at turn end, which is how they get reported.
    • 1.3 data pass, still to run, with the Codex closed: data/ YAML is never edited while it runs. From the repo root: python docs/action-log-design/probes/mark-history-hidden.py.txt --apply ticks Hidden from History on the 40 markers. Without --apply it only lists them. Commit it in data/.
    • L13 has no hook. The Elementalist's 5 x Reason rule only shows floating text; nothing ends the persistence, so "Took {n} damage in one turn" cannot appear until that rule is automated.
    • 1.4: winded, dying and killed fire where the rules already decide them, in MCDMCreature.lua, so hand edits count. Minion deaths wait for the batch that confirms them, then name the squad.
    • 1.5: resources carry the number that really changed (ReportResource). Undo on a resource line goes through History.UndoResource, which marks the line undone and keeps it.
    • 1.6: the saved path is a plain list of {x, y, floor, altitude} from path.steps, because what LuaPath:Serialize returned never reached the entry. Chunk 4.1 rebuilds a route from that list. Collisions and wall breaks are stored for the detail card; the tray only shows distance and fall.
    • Falls land after the push. The engine adds the landing as one last path step, so numSteps is one too many and path.fallDistance reads 0 afterwards. The real distance only comes with the fall event, which the engine fires when the animation ends, outside any cast. So the push leaves its row in g_falling, and the landing and the Fall Damage trigger join that row, even if it has closed. A fall with no push behind it stays a line, cause Fall Damage.
    • A creature landed on joins the push's row with the caption Landed on. With no push behind the fall it is a line, cause Landed on by {name}. Nothing is guessed from the damage, which is called Fall Damage either way: the engine fires fallenon only on creatures in the landing square, and its symbols name the faller. Tested for real, pushes in both orders, falls with no push, and a second fall inside the push's window, which stays off the row. Not tested across clients: if a trigger runs on another client it finds no push there and reads as a line, which is still true.
    • Tested for real: Brutal Slam on two clients, real heal and temporary Stamina behaviors, a Reactor trigger nested across clients, real end of turn, a real passing save, a real push with Growing Ferocity nested, a real push off a ledge in both orders (row closed before and after the landing), real Undo, and a Player seeing no Malice lines.
    • Tested with fed data only: failed saves, persistence, dying lines, confirmed minion deaths.
    • Wordings: the ones the build needed are signed off, COPY.md Round 5.
    • Left for later: effects ended by a respite (5.1), "Hidden from enemies" effects reaching players (2.4), the Active tag on a target's badge (3.1). Crows is not checked: Crowdex/ isn't in this checkout, so check a Crows game before merging.

    • 2.1: the card is a floating child of the tray's face, so it moves, scales and closes with the tray and no layout has to remember it. Tabletop.ItemRect says where the tray sits; the card picks right, then left, then inside the tray with Back (B7), and rechecks once a second, so dragging the tray moves it. It is rebuilt whenever it changes, because a scroll bar only works if it exists on its first frame.
    • Sentences: History.Story turns an entry into rows, with no gui, so the hover preview (3.3) and the sidebar preview (3.4) can use the same words. New wordings are COPY.md Round 6.
    • Which rows open a card: actions, and the Encounter ended line (L17). Every other line already says everything; L16 joins with the Why lines in 2.3.
    • W10 is not built. "Took 6 damage from 2 minions" needs the count of minions that reached a target, which entries don't hold yet. Look at it with the numbers in 2.2.
    • New facts on entries: ability.area, player, resisted names the condition when the rule text does, endedconds. Rows written before this have none of them, so an old row reads "Director" in its footer and "and Slowed ended" for a condition.
    • T13 Ally hit was missed in stage 1; it is on the target cell now, from the same check as W11.
    • Tested for real: the card on the right, on the left and inside the tray (a narrow table was faked), row swap, same row closes, close button, wheel, scroll bar drag, a row rewritten while its card is open, 31 rows built in 19 ms. Fed data only: every sentence but falls, the Encounter ended card.
    • 2.1b, a rail panel (James, 2026-11-07): History registers as a dockable panel with content, so the rail opens it as a window like Chat: frame, transparency, pin, pop out, Font Size zoom. Two generic registration fields in PresentPanel: defaultWidth (the rows are laid out for 410, plus the 8 px resize strip) and dragInPlace (rail windows are dragged without it, which restyles the whole window every frame: History's drag went from 64 ms a frame to 15; Chat's is 18). Only History sets them; giving every rail window dragInPlace is a separate change. The table item and the Tabletop.lua additions from 0.4 and 2.1 are gone. The card is placed from the window's position; popped out, it opens inside. The roll card that folds into History later (S5) aims at this window.
    • 2.1c, rows (James, 2026-11-07): a hairline above every action, folded turn and turn group (@border at 31%, the prototype's 5% white); the seam under a round heading and in the card at 75% (12%). Trigger rows are one line: the result after a caret is never cut, the "{Owner} · {trigger}" part shortens with an ellipsis and shows whole on hover. Widths are estimated per character, generously, because the engine can't measure text before layout. Tested on the seven-trigger Brutal Slam turn.
    • 2.1d, the card (James, 2026-11-07): the rail windows' frame (gradient, rounded, blurred backdrop, shadow); no white edge on the card or the selected row, which is marked by @bgRaised instead (a see-through fill shows the table behind the window under Transparent UI). A tail, a square turned 45 degrees behind the card, points at the row. The card lines up with its row from the panels' distancesToScreenEdge, slides to stay on screen, follows the list as it scrolls, and holds at the list's edge with no tail when the row scrolls out of sight. Over the list (popped out, or no room) it is solid and has no tail.
    • Performance after the feedback rounds (James: feels fine, 2026-11-07): on a freshly started Codex, idle runs at the frame cap with History open or closed; a card opens in 23-26 ms; dragging runs at 14 ms a frame; wheel scrolling at 14 ms. Two one-frame hitches stay: opening History from the rail (~95 ms) and Show all (120-140 ms for ~33 rows, 29 ms of it Lua). Spreading Show all over frames is 6.2's. Measure on a fresh start: after a day of reloads and pop outs the Codex itself slowed to ~4 frames a second, which made Show all look like a 2.7 s stall.
    • 2.2, the numbers: the prototype's receipt under What happened: Power roll (the two dice, the characteristic, a flat Bonus, edges and banes with their counts and the C4 note, Total with its tier), then a sum per target (its own roll if it had one, Tier lines by damage type, immunity or weakness, Taken / Taken, each / Regained), then Triggered and Cost. New facts: roll.natural, roll.characteristic, roll.bonus, and a target's own roll (edges, banes, total), which the roll behaviour now keeps on the cast as targetRolls beside tokenToTier. Rows written before 2.2 show only the total, the tier and the targets' sums.

    • Tested: a real Brutal Slam (5 + 5, Might 2, an edge from Prone, 14, Tier 2, 8 taken) and a fed entry with three edges and a bane, a flat bonus, a target cancelled out on its own roll, typed damage with immunity, a weakness, two goblins grouped, healing, a damaging trigger and a Malice cost.

    Risks¶

    • Performance of two encounters (0.1). Today's log keeps about 140 messages and that has drawn one complaint, so there's no value in a really long history. If two encounters cost too much, the hard cap wins and the older encounter shortens. That's why it goes first.
    • Who writes. Two clients recording the same event would double it. Each hook needs one clear writer; lapsed timers are the likeliest trouble because no single client owns them.
    • Cost on hot paths. Damage runs often, so DescribeModifications only runs when a number actually changed. Measure in 1.1.
    • Trigger causes (1.2). Nesting relies on passing the cast through events. Some events may not have one, and those fall back to a line in the turn.
    • Old log readers (6.4). Roll dialogs, respite, Encounter of the Week and others use chat messages, so 6.4 removes the panel, not the messages.
