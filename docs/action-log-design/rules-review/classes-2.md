# History rules review: Shadow, Tactician, Talent, Troubadour, Beastheart, ancestries, kits

Audit date 2026-11-04. Scope: class features, Heroic Resource rules, subclass features,
ancestry traits and kit rules that fire on their own or change numbers without an action,
plus abilities whose effect sets up a later automatic event. Ordinary abilities used as
actions are skipped. Code and data were read, not run; nothing was checked in the app.

**Paths.** `R:n` = `ClaudeBridge/ClaudeRefHeroes.lua` line n (the Heroes book as text).
`B:n` = `beastheart-reference.md` line n (it sits at the repo root, not in
`Draw Steel Beastheart/`). Data paths are under `data/objectTables/`: `c/` classes,
`s/` subclasses, `e/` characterongoingeffects, `cd/` charconditions, `anc/` races,
`k/` kits, `a/` adventuretables, `sa/` standardabilities, `g/` globalrulemods; `m/` is
`data/monsters/`. The YAML line is the feature or trigger that does the work. Implementation
tags quoted as Gold/Silver/Bronze/Unimpl are the data's own `implementation` field (4/3/2/1).

**Draft lines** are proposals for sign-off, in COPY.md style (past tense, result first,
names not pronouns, Hero and Stamina capitalised, conditions lower case inside sentences).
Example names: Human Shadow, High Elf Tactician, Time Raider Talent, Polder Troubadour,
Orc Beastheart and their companion Wolf.

## How the codex decides what reaches the log (same mechanism as classes-1.md)

1. Automatic triggered abilities never post a cast card: `TriggeredAbility.mandatory`
   defaults to true (`DMHub Game Rules/TriggeredAbility.lua:967`) and
   `ShowChatMessageOnCast()` returns `not self.mandatory` (`:2644`). Heroic Resource
   triggers use the setting id `game:heroicresourcetriggers` (a truthy string), so they post
   no cast card either.
2. An automatic event is visible only when one of its behaviors posts its own card, and
   nearly all of them do so only when the author typed a `chatMessage` (Replenish, Damage,
   Heal, Grant Temporary Stamina, Purge Effects). Heroic Resource gains linked to a class
   checklist item always post a resource line whose reason is the checklist name
   (`DMHub Game Rules/AbilityReplenish.lua:661-728`), which also gates them once per
   round/encounter (`:348-366`).
3. Flat damage from an automatic trigger with no `chatMessage` is silent: the damage roll
   is deterministic, so the roll dialog resolves it with `silent = true`
   (`Timeline/EmbeddedRollDialog.lua:6890-6936`).
4. Prompted triggers (`mandatory: false`) post a cast card when accepted; per-target
   results sit in its hover.
5. Power-table triggered actions (`behavior: powertabletrigger`, e.g. Defensive Roll,
   Parry, Repel) are taken inside another creature's roll or damage dialog; they post
   nothing of their own (`Draw Steel Core Rules/PowerTableTriggers.lua` has no chat call).
6. Passive edges, banes, damage bonuses and cost changes fold into the roll. The roll
   record keeps the kept modifier names (`Draw Steel UI/DSRollDialog.lua:3963-3976`) but no
   card shows them as a reason. Kit bonuses are folded into the ability text before the
   roll; the ability card says "Includes +2 damage from Shining Armor kit"
   (`Draw Steel Core Rules/MCDMKit.lua:471-476`), the log says nothing.
7. Effects ending (by duration, on dying, at end of encounter, or by a Purge with no
   `chatMessage`) are never logged. Recoveries spent because a feature allowed it log as a
   bare "Use Recovery" resource line with no cause (`g/triggers.yaml:14-51`).

**Logged today codes.** RES = resource line with the quoted reason. DMG = damage line with
the quoted text. TMP = temporary Stamina line. HEAL = Stamina regained line. PURGE = effects
removed line. CAST = cast card (ability used or prompted trigger accepted). ROLL = only
inside a roll. CHIP = immunity/weakness chip (`DamageModifierChatMessage`). FLOAT = floating
text over the token, not in the log. NO = nothing.

**Row types.** Action = action row. Nested = triggered row under what set it off. Turn line
/ Resource line / Ended line = compact lines with no action. Why = detail-card Why line
(**lead** / sentence, COPY.md R1).
