    History rules review: the Director's side¶

    Audit date 2026-11-04. Scope: Malice, villain actions, minions and captains, solos, leaders, retainers, reinforcements and objectives, dynamic terrain and hazards, auras, monster traits that fire on their own, end of encounter. Code was read, not run; nothing was checked in the app.

    Rule references: CRM = ClaudeBridge/ClaudeRefMonsters.lua (the Monsters book as text), MR = monster-reference.md (stat blocks; also holds the Dynamic Terrain stat blocks from line ~23700). Code paths are repo-relative. Data counts are from data/monsters/*.yaml unless stated.

    Every draft line below is a proposal for sign-off (COPY.md style: past tense, result first, names not pronouns, Hero and Stamina capitalised, conditions lower case inside sentences). IDs from COPY.md (W, Y, T, C) are cited where an existing pattern fits.

    Five codex facts that shape most rows¶

    1. Automatic triggers post no cast card. TriggeredAbility.mandatory defaults to true (DMHub Game Rules/TriggeredAbility.lua:967) and TriggeredAbility:ShowChatMessageOnCast() returns not self.mandatory (:2644). So a trait that "just happens" (Loyalty Collar, Infernal Ichor, Toxiferous, aura entry effects) never names itself in the Action Log.
    2. Flat rule-text damage posts nothing at all. Tier/rule text such as "2 fire damage" goes straight to InflictDamageInstance with no roll dialog (Draw Steel Core Rules/MCDMAbilityBehavior.lua:330-414); only dice damage opens a roll ("{ability}: Roll for Damage", Draw Steel Ability Behaviors/AbilityDamage.lua:157). A mandatory trait dealing flat damage is invisible unless an immunity or weakness changed it (DamageModifierChatMessage, MCDMCreature.lua:5793).
    3. Malice changes are recorded, but not in the log. Every SetMalice appends a note to a StatHistory in the globalResourcesv2 document (DMHub Game Rules/Resource.lua:40-75), shown only as a hover tooltip on the Director's action-bar Malice counter (DrawSteelActionBar/DrawSteelActionBar.lua:3011) and in the Encounter Wrangler. Only spending through ConsumeResources posts a card (MaliceSpentChatMessage, Draw Steel Core Rules/DSResources.lua:103-277).
    4. Minion deaths are confirmed, not computed. The squad pool owes deaths; the attacker's controller (a player, when a Hero dealt the damage) clicks red skulls or "Choose for me" (direct targets first, then nearest), and squad-death triggers wait for those confirmations (Draw Steel UI/DrawSteelTokenHud.lua:25-238, Draw Steel Core Rules/MCDMCreature.lua:6020-6270). History must record the confirmed deaths, not the pool arithmetic.
    5. Winded, dying and killed are events with sounds, never log entries (MCDMCreature.lua:6720-6812). BeginRoundChatMessage shows only "Draw Steel!" / "ROUND n" (MCDMInitiativeBar.lua:6921-6985); StartOfTurnChatMessage only "Start of Turn".

    An existing structured source History can build on: LiveEncounter keeps per-token, per-round stats and writes a permanent battle record at encounter end (Draw Steel Core Rules/MCDMEncounter.lua:2320-2400, 2925-2960, 3504).

    Legend¶

    • Row types: Action row (an action or Malice feature someone used); Nested (a triggered effect under what set it off); Turn line (start/end of turn, T16); Round line (round heading T5 or a compact line at the round boundary); Compact line (anything with no action); Why (detail card, R1 format: bold lead, then one sentence); Caption (T14).
    • Players see it: what a player could know at the table. "If Malice shown" = the Director's choice the rules allow (CRM:785-790); the codex has a per-tracker public/private choice (DMHub Game Hud/TableDice.lua:560). Hidden tokens and hidden zones stay Director-only until revealed.
