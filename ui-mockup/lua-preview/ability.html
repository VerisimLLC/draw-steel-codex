What the ability editor adds to the class builder's pieces

Same module

One editor, two hosts

The shelf, block rows, slivers, menus and checks are the class builder's own panels. The ability editor is the same module with a different host: its sections, its blocks and the live card. The class builder opens it as a modal for a feature's ability.

Same

Power roll tiers

A power roll block holds three rows, each a fixed-width tier label and its own block stack. No special shape is needed: a coloured panel with inner panels. The tier steps save back into the tier text ("3 + M damage; slide 2").

Same

Only the right slots light up

Each sliver says what fits there in data.slot, and the dragged block's canDragOnto checks it, so the engine only marks slots that accept the block. Drag "Damage" from the shelf: only the tier slots open.

Same

Fixed lines have no grip

What it is and who it targets are always there, so they are one coloured group with rows split by a hairline and no drag handle. Only steps move.

Changes

The card is the real one

The web prototype drew its own parchment card. In Lua the preview is the existing ability tooltip, as AbilityEditor's preview column shows it, so it always matches the game. Clicking a line to reword it needs the tooltip to report which line was clicked.

Changes

One colour table for both editors

The two web prototypes used slightly different values for some groups (resources, logic). In Lua both read one BEStyles.BlockColors table, so a resource block is the same gold in both.
